# Evolución por fases

1. **Cierre técnico de etapa 1:** compilar y probar instalador Windows, validar arranque/reinicio de servicios y restauración real, añadir pruebas de integración con PostgreSQL y fallos inducidos, proteger mejor auditoría/transacciones, flujo guiado para cambiar contraseña propia y respaldo programado. Antes de producción, prueba de recuperación en equipo distinto.
2. **Sociedades y programación semanal (base implementada):** entidades sociedad, culto, semana con identificador y rango único, versión publicada inmutable y borradores independientes. Asignación Damas/Caballeros alternada por regla predeterminada y nunca ambas para un mismo culto; una selección manual explícita prevalece para actividades extraordinarias. Guardar una semana nueva jamás actualiza filas de semanas anteriores. Generar asignaciones el domingo para martes, miércoles, jueves y domingo siguiente, con notificación inicial y recordatorios futuros.
3. **Contenido (temas, invitaciones y bosquejos implementados; faltan paneles adicionales):** tema y palabra bíblica de búsqueda para Damas/Caballeros, versículo que cada participante busca y aprende, bosquejos, invitaciones y dashboard. Exportación legible por culto y semana.
4. **Finanzas (ingreso, gasto, decisión, pago, cuentas y presupuesto implementados):** ampliar cuentas por pagar, nómina, conciliación bancaria, reportes históricos y permisos de operación antes de uso contable oficial. Quien registra no aprueba ni paga el mismo gasto y el aprobador no lo paga.
5. **Comunicaciones y LAN:** separar canal de mensajes, agregar cola de envío por consentimiento explícito, documentar entrega; para LAN configurar host de API y Postgres, firewall y TLS, y revisar CORS/orígenes, autenticación, privilegios del servicio y copias. La versión actual escucha solo localhost; cambiar solo API_HOST no basta para exponerla con seguridad.

La base actual define identificadores de miembros, usuarios y roles; las tablas futuras deben enlazar por claves externas y nuevas migraciones incrementales. No incorporar decisiones de distribución antes de validar el flujo local.
